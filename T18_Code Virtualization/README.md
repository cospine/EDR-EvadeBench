# T18: Code Virtualization (VMProtect)

**DET classification:** Detection → Obfuscation

This technique involves transforming the core logic of the malicious code into virtual machine (VM) bytecode using advanced commercial tools like **VMProtect**. The VMProtect engine replaces native machine instructions with its own custom instruction set, which is then executed by a small, complex Virtual Machine Monitor (VMM) embedded within the protected binary.

The primary evasion goals are:

1.  **Anti-Static Analysis:** The virtualized code cannot be disassembled or decompiled by standard tools.
2.  **Anti-Dynamic Analysis:** It makes symbolic execution and dynamic tracing (used by EDR sandboxes) extremely difficult due to the complex, obfuscated flow inside the VMM.
3.  **Signature Evasion:** The native code is entirely replaced, completely breaking signature matching.

This represents a high-end obfuscation technique that forces EDRs to rely on behavioral detection of the VMM itself or high-latency analysis.

## ⚙️ Usage (Defensive Research)

The implementation requires the use of the VMProtect application to process the compiled evasion sample. VMProtect is commercial software, so this folder provides documentation only (no project files); the technique is applied as a post-processing step on your compiled sample.

### Prerequisites

* The **VMProtect** application (commercial software) is required.
* A compiled PE file (e.g., your own payload loader built from this repository's sources) to be used as the target file.

### Detailed Execution Steps

1.  **Tool Setup:**
    * Install and configure the VMProtect application according to its documentation.

2.  **Apply Virtualization:**
    * Load the target executable (`your_evasion_sample.exe`) into the VMProtect application.
    * Mark the critical functions containing the shellcode loader or decryption logic for **Virtualization**.
    * Process the file to produce the protected output binary.

3.  **Validation:**
    * Run the protected executable against the target EDR to assess detection.
    * Attempt to reverse-engineer the protected binary using tools like IDA Pro; you should confirm that the virtualized sections are unrecognizable as native code.

> **Warning:** Code virtualization tools are often complex and sensitive. Execute this PoC **only** in isolated VM environments. Use of cracked or unlicensed software for this PoC is strictly prohibited.
